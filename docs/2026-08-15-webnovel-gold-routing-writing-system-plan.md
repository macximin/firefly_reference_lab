## 1. 목적

이 계획의 목표는 잘 분석된 작품의 상업 골격을 실제 신작 생산에 쓰는 것이다. 승인 골드 하나를 주축으로 삼아 업종·사건열·보상 리듬을 보존하고, 다른 골드에서 필요한 사건·압박·반전·관계 보상을 라우팅한다.

최종 문장은 한 명의 Lead Writer가 책임진다. 골드 레퍼런스는 추상 조언만 하는 편집 메모가 아니라, 주축 장편 엔진과 실제 사건·보상 은행으로 사용한다.

현재 관리자 QA까지 통과한 골드는 다음 두 작품이다.

| 작품 | 우선 활용 영역 | 주의점 |
| --- | --- | --- |
| 《독식하는 재벌 3세》 | 사업·소유·지위 상승, 거래와 공개적 승리, 장기 스케일 확장 | 원문 문장·고유 대사·허구 고유명만 직접 전사하지 않는다 |
| 《리턴 에이스》 | 경쟁·훈련·기록·공개 검증, 경기 보상과 커리어 상승 | 원문 문장·고유 대사·허구 고유명만 직접 전사하지 않는다 |

《리턴 에이스》는 초기 분석에서 기계식 페이싱과 옴니버스 Arc 문제로 반려됐으나, 310회 수동 페이싱·종료 훅·회차 사실 전수 재감리와 자연 NarrativeArc 55개 재분절을 마쳤다. 2026-08-15 strict 오류 0·경고 0과 관리자 QA 15/15 PASS 후 긍정 골드로 승격됐다.

## 2. 운영 원칙

1. 최종 산문은 Lead Writer 한 명이 쓴다.
2. 작품의 캐논과 사용자 지시가 모든 레퍼런스보다 높은 권위를 가진다.
3. 골드는 작품 단위로 평균 내지 않고, 해결할 문제와 역할에 따라 배정한다.
4. 계획은 가설이다. 실제로 쓰인 장면과 독자가 받은 보상을 영수증으로 남기고 다음 계획을 갱신한다.
5. 상업성은 기대와 지급의 관리로 본다. 독창성·참신성·원작과의 거리는 별도 점수로 관리하지 않는다.
6. 정합성 판단은 현실 고증보다 재미, 기대, 감정적 납득을 우선한다.
7. 인물·장소·물건·호칭·목격자 반응 같은 작품 표면을 추상 분석어보다 먼저 보존한다.

## 3. 두 개의 관리 루프

### 3.1 상업성 하한선

상업성 루프는 독자가 무엇을 기대했고 무엇을 실제로 받았는지를 관리한다.

- 작품 전체의 독자 약속 3~5개
- 현재 아크가 해결할 유료 질문
- 각 화에서 지급할 작은 가치
- 아크 끝에서 눈에 보이게 결산할 큰 보상
- 아직 갚지 않고 다음 아크로 넘길 독자 부채
- 연재 단계별 과제
  - 1~5화: 계약 발화와 즉시 체감 보상
  - 6~30화: 반복 가능한 재미 엔진 정착
  - 중반: 보상 통화와 관계·무대의 확장
  - 장기 연재: 반복 피로 방지와 새 압력 도입
  - 종결부: 핵심 약속 회수와 최종 상태의 가시화

향후 조회·잔존·결제 같은 실제 독자 지표를 연결할 수 있다. 다만 지표는 문제를 발견하는 신호로만 사용하고, 서사 결정을 자동으로 대체하지 않는다.

### 3.2 골격 보존과 라우팅

주축 골드 한 편에서 주업종, 반복 동사, 초반 진입, 보상 리듬과 장기 성장 사다리를 잠근다. 보조 골드는 현재 Arc에 필요한 사건·압박·반전·보상·관계 변화를 공급한다.

같은 업종, 비슷한 사건 순서와 보상 구조는 결함으로 보지 않는다. 주인공 캐논과 충돌하는 원인·담당 인물·시점만 필요한 만큼 조정한다. 낯설게 보이기 위해 산업이나 능력을 비틀지 않는다.

## 4. 골드 라우팅 방식

골드는 고정 비율로 섞지 않는다. 현재 판단에 필요한 관할을 부여한다.

| 역할 | 담당 판단 |
| --- | --- |
| Spine | 장기 성장, 아크 경계, 다음 단계로 넘어가는 비가역 변화 |
| Engine | 반복 가능한 회차 재미와 행동 루프 |
| Payoff | 보상 통화, 지급 장면, 목격자와 후속 파장 |
| Emotion | 관계 변화, 감정적 대가, 결산 뒤의 여진 |
| Hook | 화말 프레임, 열린 질문, 다음 압력 |
| Wildcard | 익숙한 장르 문법을 깨지 않는 범위의 낯선 장면 원리 |

작품 전체를 이끄는 주 골드는 비교적 안정적으로 유지할 수 있다. 아크나 회차의 문제를 해결하는 전문 골드는 필요할 때 바꾼다.

초기 권장 상한은 다음과 같다. 이는 확정 규칙이 아니라 논의 대상이다.

- Spine 1개
- 현재 문제를 맡는 전문 골드 최대 2개
- 필요한 경우 Wildcard 1개

한 판단에 서로 다른 골드가 충돌하면 평균을 내지 않는다. 먼저 각 골드의 관할을 분리하고, Lead Writer가 현재 작품의 독자 약속과 캐논을 기준으로 선택한다.

권위 순서는 다음과 같다.

`사용자 의도·작품 캐논 → Series Contract → 현재 NarrativeArc → 선택된 골드 역할 → 일반 장르 지식`

## 5. 집필 흐름

```mermaid
flowchart LR
    A["Series Contract"] --> B["현재 단계와 문제 진단"]
    B --> C["Gold Router"]
    C --> D["NarrativeArc 후보 3안"]
    D --> E["Lead Writer 선택"]
    E --> F["ArcPacket 1~3화"]
    F --> G["초고 집필"]
    G --> H["상업성·창의성 감리"]
    H --> I["Reward Receipt"]
    I --> J["다음 계획 Reflow"]
```

1. Series Contract에서 작품 전체의 독자 약속과 금지선을 확인한다.
2. 현재 연재 단계와 막힌 문제를 진단한다.
3. 문제별로 골드 역할을 배정한다.
4. 시장 안전안·인물 중심안·와일드카드안의 NarrativeArc 후보를 만든다.
5. Lead Writer가 하나를 선택하거나 필요한 부분만 재조립한다.
6. 선택한 NarrativeArc에서 다음 1~3화만 ArcPacket으로 구체화한다.
7. Lead Writer가 초고를 쓴다.
8. 상업성 감리와 창의성 감리가 초고를 따로 비평한다. 두 감리는 최종 문장을 공동 집필하지 않는다.
9. 실제 장면에서 무엇이 지급되고 무엇이 변했는지 Reward Receipt로 남긴다.
10. 영수증을 근거로 아직 쓰지 않은 계획만 Reflow한다.

## 6. 필요한 계획 단위

### 6.1 Series Contract

실행 템플릿: `templates/writing-system/01-series-contract.md`

- 독자가 계속 읽으며 기대할 핵심 약속 3~5개
- 주인공의 장기 욕망과 결핍
- 작품의 반복 재미 엔진
- 대표 보상 통화
- 이 작품에서 훼손하면 안 되는 말맛과 표면
- 피해야 할 평탄화와 장르 배신

### 6.2 Gold Reference Card

실행 템플릿: `templates/writing-system/gold-reference-card.md`

검증된 작품마다 다음 내용을 짧게 관리한다.

- `best_at`: 이 작품이 특히 잘하는 판단
- 자연스러운 아크 경계 패턴
- 작은 보상과 큰 결산의 통화
- 화말 훅의 유형
- 관계·지위 변화가 보이는 장면 영수증
- 다른 작품에 옮기면 안 되는 고유 사건과 표면
- 분석 과정에서 발견된 실패 패턴

### 6.3 NarrativeArc Card

실행 템플릿: `templates/writing-system/03-narrative-arc-v2.md`

- 독자가 돈을 내고 확인할 아크 질문
- 시작 상태와 종료 시의 비가역 변화
- 주인공이 내려야 할 구체적 선택
- 인물·장소·물건·상대·공개 장면 등 표면 앵커
- 소지급의 계단과 대결산
- 결산을 목격하고 반응할 인물이나 세계
- 갚을 독자 부채와 다음 아크로 넘길 부채
- 선택한 골드의 역할과 선택 이유
- 이 작품에서만 가능한 대표 장면

### 6.4 ArcPacket

실행 템플릿: `templates/writing-system/04-chapter-packet.md`

NarrativeArc 전체를 한 번에 고정하지 않고 다음 1~3화만 제작 단위로 만든다.

- 각 화의 진입 상태와 즉시 목표
- 저항과 압력 상승
- 전환점과 선택
- 이번 화의 작은 지급
- 다음 화를 열어 두는 구체적 마지막 프레임
- 반드시 살릴 표면과 피해야 할 기계적 표현

### 6.5 Reward Receipt

실행 템플릿: `templates/writing-system/05-reward-pacing-ledger.md`

초고 또는 확정 원고를 기준으로 기록한다.

- 독자가 실제로 본 행동과 결과
- 지급된 약속, 유예된 약속, 새로 생긴 부채
- 인물 관계·지위·능력·소유 상태의 전후 변화
- 지급을 목격한 인물과 반응
- 보상 뒤에 남은 비용과 감정적 여진
- 앞으로의 계획에서 수정할 부분

## 7. 골드 라이브러리 확장 순서

작품 수를 먼저 늘리지 않는다. 현재 비어 있는 능력 슬롯을 채운다.

| 우선순위 | 능력 슬롯 | 현재 상태 |
| --- | --- | --- |
| 1 | 사업·소유·지위 상승 | 《독식하는 재벌 3세》 확보 |
| 2 | 경쟁·훈련·공개 검증 | 《리턴 에이스》 확보 |
| 3 | 관계·감정·로맨스 결산 | 다음 골드 후보 필요 |
| 4 | 전투·성장·세계 규칙 | 후보 필요 |
| 5 | 미스터리·복선·정보 통제 | 후보 필요 |
| 6 | 장기 연재 종결·핵심 약속 회수 | 후보 필요 |

새 골드는 원문 전수 분석, strict 검증, 관리자 수동 QA를 모두 통과한 뒤 라이브러리에 들어간다. 형식만 통과했거나 기계적 분절이 발견된 분석은 긍정 레퍼런스로 사용하지 않는다. 대신 피해야 할 패턴을 기록하는 Anti-Gold 자료로 보존한다.

## 8. 실패 방지 규칙

- 원문의 문장·고유 대사·허구 고유명과 긴 장면 묘사를 직접 전사하지 않는다.
- 승인 골드의 업종·사건 유형·사건 순서·보상 구조와 관계 변화 문법은 라우팅할 수 있다.
- 아크 수나 길이를 먼저 정하고 원문 또는 신작을 맞춰 자르지 않는다.
- 다음 화의 완결 사실을 현재 화의 지급으로 앞당기지 않는다.
- 키워드 산식으로 긴장·보상·훅 점수를 확정하지 않는다.
- 관계 상승을 추상 라벨로 선언하지 않는다. 호칭, 자리, 행동, 계약, 목격자 반응 같은 장면 증거를 둔다.
- 여러 골드의 문장과 사건을 한 초고에 섞지 않는다.
- 같은 종류의 승리와 보상을 이름만 바꿔 반복하지 않는다.
- 확정된 원고는 기본적으로 되감지 않는다. Reflow는 아직 쓰지 않은 미래 계획을 대상으로 한다.

## 9. P9 진입 게이트

P9는 문서 작성이 아니라 실제 작품으로 집필 루프를 검증하는 단계다. 아래가 모두 준비된 뒤에만 시작한다.

- 작품소개가 포함된 `project_pitch.md`
- 채워진 Series Contract
- 채워진 Entry Contract
- 첫 3개 NarrativeArc v2
- 첫 1~3화 Chapter Packet
- Reward & Pacing 계획표
- 주요 조연 Character Utility Card
- Gold Router의 주축 골격·보조 사건 은행·직접 전사 금지선

《부도난 회사만 삽니다》 팩은 위 자료를 갖췄고 삭제 전 InkOS 시험 프로젝트와 1화까지 생성됐으나, 2026-08-17 사용자가 작품을 거부하고 삭제했다. 이 후보는 P9 완료 증거가 아니며 새 승인 없이 복구할 수 없다. P9 실험은 사용자가 선택한 새 작품 또는 명시적으로 승인한 기존 InkOS 작품에서 다시 시작한다.

### 단계 A: 수동 라우팅 실험

하나의 신작 또는 기존 InkOS 작품에서 한 개 NarrativeArc만 골라 수동으로 시험한다. Lead Writer가 주축 골드 하나를 고정하고, 다른 골드에서 사건과 보상을 골라 하나의 결합안을 만든다.

완료 조건:

- 주축 골드의 상업 골격이 불필요하게 해체되지 않았는가
- 보조 골드의 사건과 보상이 실제 Arc에 배치됐는가
- 독자 약속과 지급이 전보다 선명해졌는가
- 최종 문장에 여러 작가가 섞인 느낌이 없는가

### 단계 B: 카드 규격 확정

수동 실험 결과를 바탕으로 Series Contract, Gold Reference Card, NarrativeArc Card, Reward Receipt의 최소 필드를 확정한다. 작성 부담이 집필 이익보다 크면 필드를 줄인다.

### 단계 C: InkOS 연결 설계

카드 규격이 실제 집필에서 유효하다고 확인된 뒤에만 InkOS의 NarrativeArc, ArcPacket, Forecast, Reflow, Studio 화면과 연결하는 구현안을 별도로 만든다.

### 단계 D: 골드 능력 슬롯 확장

관계·감정 골드를 우선 추가한 뒤, 실제 신작에서 자주 막히는 기능을 기준으로 다음 슬롯을 채운다.
