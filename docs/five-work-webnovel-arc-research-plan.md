## 2. 역할 분리

### 관리자 세션

현재 세션 하나가 끝까지 총괄한다.

- 공통 분석 계약과 입력 경로, 네 가지 Goal을 고정한다.
- 작품별 세션 5개를 만들고 각 세션에 작품 하나만 배정한다.
- 진행 상태, 조기 종료, 질문, 산출물 누락을 감시한다.
- 작품 세션이 다른 작품 폴더나 공통 파일을 수정하지 못하게 한다.
- 5개 결과를 직접 검증한 뒤 표면을 훼손하지 않는 범위에서 공통형·변형형·작가 고유형으로 분리한다.
- 통합 모델을 같은 5개 세션에 다시 보내 반례 검사를 받는다.
- 최종 InkOS Arc 계약만 관리자 세션이 작성하고 커밋한다.

### 작품별 세션

- 한 세션은 원문 한 편만 담당한다.
- 다른 작품 분석과 중국 숏드라마 보고서를 보지 않은 상태에서 1차 분석한다.
- 담당 산출물 폴더 밖을 수정하지 않는다.
- 커밋·푸시하지 않는다. 관리자가 검수 후 한 번에 반영한다.
- 표본 분석으로 완료 처리하지 않고, 파일의 첫 표식부터 마지막 표식까지 전 범위를 매핑한다.
- 인물 이름·구체 사건·장소·사업·경기·물건·관계 변화·승패·보상을 실제 작품 표면 그대로 살린다.
- 현실 고증보다 독자가 느끼는 재미의 인과와 감정적 납득을 우선한다.
- 과잉 분류, 미세 오류 집착, 논리 동작 중심의 추상화, 기계적인 문체를 피한다.

## 3. 세션 실행 방식

원문은 Git 제외 로컬 폴더에 있으므로 다섯 세션 모두 `inkos_reverse_lab` 저장 프로젝트를 **로컬 모드**로 연다. 별도 Git worktree에서는 원문이 보이지 않기 때문이다.

동시 쓰기 충돌을 막기 위해 작품별 출력 폴더를 고정한다. 공통 문서와 도구는 읽기 전용이며, 작품 세션은 자기 폴더만 쓴다. 다섯 세션 모두 `gpt-5.6-sol`, 추론 `ultra`, Fast 모드 `빠름`으로 고정한다. 이하 운영 표기는 `솔트라`다.

예정 제목:

1. `InkOS Arc 1/5 · 금수저 투자백서`
2. `InkOS Arc 2/5 · 독식하는 재벌 3세`
3. `InkOS Arc 3/5 · 마법 배운 재벌집 늦둥이`
4. `InkOS Arc 4/5 · 이혼 후 재벌 각성`
5. `InkOS Arc 5/5 · 리턴 에이스`

## 4. 공통 분석 절차

### Pass A. 입력 고정과 회차 분할

- 정확한 파일 경로와 SHA-256을 기록한다.
- `ⓚ`로 시작하는 표식을 파일 순서대로 인덱싱한다.
- 표시된 회차 번호가 건너뛰거나 중복되어도 임의 보정하지 않는다.
- 각 회차의 시작·끝 행과 제목을 기록한다.

### Pass B. 작품 표면 복원

먼저 작품 자체를 다른 사람이 읽지 않고도 따라갈 수 있는 대형 기획서로 복원한다.

- 실제 주인공·주요 인물과 욕망·관계
- 출발 상태와 장기 목표
- 세계·시대·직업·사업·경기 규칙
- 핵심 능력·자원·물건·조직
- 주요 적대자와 경쟁 구도
- 초반·중반·후반의 구체 사건 흐름
- 반복되는 재미와 대표 보상 장면
- 결말까지의 변화와 최종 상태

### Pass C. 회차 전수 지도

모든 회차를 아래 필드로 한 줄씩 요약한다.

- 진입 상태
- 이번 화의 독자 약속
- 주인공 목표와 행동
- 저항·비용
- 전환 또는 새 정보
- 이번 화에 실제 지급된 보상
- 돈·능력·지위·관계·세계 중 바뀐 상태
- 마지막 훅
- 닫힌 루프와 새로 열린 루프

표면 요약은 이름 없는 `주인공`, `기관`, `증거`, `보상` 같은 칸 채우기로 대체하지 않는다. 실제 이름과 사건을 먼저 쓰고, 분석어는 그 뒤에 붙인다.

### Pass D. Arc 경계 탐지

Arc 길이를 미리 1~3화나 5화로 고정하지 않는다. 다음 신호 중 둘 이상이 동시에 발생한 곳을 경계 후보로 잡는다.

- 지배 목표가 바뀐다.
- 주요 상대·기관·경기·장소가 바뀐다.
- 누적 약속이 보상 또는 실패로 결산된다.
- 핵심 열린 루프가 닫히고 다음 루프가 전면에 나온다.
- 돈·능력·지위·관계·세계 상태가 되돌리기 어렵게 바뀐다.
- 시간 점프, 시즌 전환, 주요 인물군 교체가 일어난다.

후보 경계를 다시 원문으로 확인해 실제 Arc로 확정한다. Arc마다 작품 속 사건을 반영한 고유 이름을 붙인다. 시작/끝 회차, 등장인물, 장소, 사건 발단, 회차별 구체 비트, 압력 상승, 중간 전환, 결산 장면, 관계·지위·능력 변화, 다음 Arc 연결고리를 기록한다.

### Pass E. Arc별 페이싱 구조도

각 Arc에 다음을 모두 붙인다.

- 회차별 핵심 사건과 종료 훅
- `도입 → 약속 → 전진 → 압박 → 전환 → 보상 → 여진/다음 훅`의 실제 배치
- 회차별 긴장도·보상도·훅 강도 1~10
- 정보 공개, 행동, 관계, 감정, 물질·지위 보상의 비중
- 빠르게 넘긴 구간과 충분히 머문 구간
- Arc가 느려지거나 급해진 지점과 재미 기준의 판단

중국 보고서처럼 몇 개의 거시 블록으로 접어 버리지 않는다. 산출물 크기에는 상한을 두지 않으며, 작품의 모든 Arc를 구체적으로 펼친다.

### Pass F. InkOS 적용과 자유 개선

현재 InkOS의 기획서 → Arc → 원고 흐름, Arc 스키마, Rails·Forecast·감리 표면을 읽고 담당 작품을 실제로 운용한다면 무엇이 유지되고 무엇이 빠지는지 분석한다.

- 현재 기능으로 그대로 가능한 작업
- 구조 자체를 바꿔야 하는 부분
- 기존 구조는 유지하고 보정층으로 해결할 부분
- 표면 정보가 추상 필드로 말라버리지 않게 하는 장치
- Arc별 페이싱 계획·감리·재조정 방식
- 작품별 자유 개선안

## 5. 작품별 필수 산출물

각 작품 세션에는 다음 네 가지 Goal을 준다. 데이터 크기에는 상한이 없다.

1. **각 작품별 기획서**: 작품의 실제 인물·사건·세계·관계·보상을 보존한 전체 기획서
2. **각 작품별 Arc 구조도**: 모든 Arc의 구체 사건 흐름과 회차별 페이싱
3. **InkOS 사용·구조 개선 보고서**: 이 작품을 InkOS로 쓰는 법, 구조 변경 또는 보정층 필요성
4. **기타 자유 개선 사항 보고서**: 분석 중 발견한 창작·UI·워크플로·감리 개선안

각 작품 폴더에는 최소 다음 파일을 만든다.

| 파일 | 내용 |
| --- | --- |
| `source_receipt.json` | 입력 경로, 해시, 표식 수, 첫/끝 표식, 번호 이상 여부 |
| `chapter_map.csv` | 전 회차의 Episode Loop 필드 |
| `project_bible.md` | Goal 1. 작품 표면을 살린 대형 기획서 |
| `arc_map.csv` | Goal 2. 탐지된 모든 Arc의 시작/끝과 구체 구조 필드 |
| `arc_pacing.csv` | Goal 2. 회차별 Arc 단계·긴장도·보상도·훅 강도 |
| `arc_atlas.md` | Goal 2. 모든 Arc의 고유 이름·사건·인물·장소·회차별 비트와 전체 구조도 |
| `inkos_usage_and_gap_report.md` | Goal 3. 현재 사용법, 구조 개선, 보정층 제안 |
| `free_improvements_report.md` | Goal 4. 자유 개선 사항 |
| `completion_receipt.md` | 전수 범위, 미확정 구간, 자체 반례 검사 결과 |

공통 형식은 `templates/work-arc-analysis-contract.md`를 따른다.

## 6. 관리자 검수

작품 세션이 완료를 말해도 다음을 통과하기 전에는 완료로 받지 않는다.

- `source_receipt.json`의 해시가 실제 원문과 일치한다.
- `chapter_map.csv` 행 수가 실제 표식 수와 일치한다.
- `project_bible.md`만 읽어도 작품의 실제 인물·사건·장기 진행과 결말을 따라갈 수 있다.
- `arc_map.csv`의 시작/끝이 겹치거나 비어 있지 않다.
- 모든 Arc에 고유 이름, 구체 사건, 회차별 페이싱이 있다.
- 모든 회차가 정확히 하나의 Arc 또는 명시적인 전이 구간에 속한다.
- `arc_atlas.md`의 주장마다 회차 범위가 있다.
- 초반 표본만으로 후반을 추정하지 않았다.
- 고정 길이 템플릿을 원문에 억지로 맞추지 않았다.
- 추상 분석어가 작품 표면을 대체하지 않았다.
- 현실성 지적보다 재미의 약속·보상·감정적 납득을 기준으로 판단했다.
- 네 가지 Goal이 각각 독립 문서로 완료됐다.

누락이 있으면 관리자가 해당 세션에 같은 작업을 다시 보내 보완하게 한다. 새 세션을 만들지 않는다.

## 7. 5작품 통합

5개 결과가 모두 검수된 뒤 관리자가 다음 순서로 합친다.

1. 작품별 기획서와 Arc 구조도를 보존한 채 Arc 길이 분포와 페이싱을 비교한다.
2. 4~5작품에서 반복되는 요소를 `공통형`으로 분류한다.
3. 2~3작품에서 장르에 따라 달라지는 요소를 `변형형`으로 분류한다.
4. 한 작품 또는 한 필명에만 나타나는 요소는 `고유형`으로 남긴다.
5. 중국 숏드라마 보고서는 이 시점에 처음 열어, 숏드라마 특유 요소와 웹소설 공통 요소를 대조한다. 기존 중국 구조도의 낮은 해상도를 답습하지 않고, 새 웹소설 구조도는 훨씬 큰 전수 데이터로 유지한다. 중국 보고서에만 있는 구조는 InkOS 기본값으로 채택하지 않는다.
6. 통합 초안을 기존 5개 세션에 돌려 각 담당 작품에서 깨지는 지점과 반례를 제출받는다.
7. 반례를 반영한 뒤 두 번째 관리자 검수에서 결론이 유지되면 v1로 확정한다.
